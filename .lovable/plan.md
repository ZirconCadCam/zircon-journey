## الهدف
تطوير دورة ثانية لمستوى تقدم الحالة بعد وصول الأسنان المؤقتة للسكرتارية وتركيبها على المريض، تنتهي بتصنيع الأسنان الدائمة وأرشفة الحالة.

## دورة الحياة الجديدة الكاملة
```
حالة جديدة → قيد التصميم → تم التصميم → قيد التصنيع →
تم تصنيع المؤقت → تم ترحيل المؤقت → قيد المراجعة لدى الطبيب →
[فرع A: اعتماد نهائي]  أو  [فرع B: يتطلب تعديل → قيد تعديل التصميم → تعديل معتمد] →
قيد تصنيع الدائم → تم تصنيع الدائم → تم ترحيل الدائم → مؤرشف
```

## تغييرات قاعدة البيانات (slot_cases)
أعمدة جديدة منطقية:
- `temporary_delivered` boolean — تأكيد الطبيب استلام المؤقت
- `doctor_decision` text — `null | 'approved' | 'revision'`
- `revision_notes` text — ملاحظات التعديل من الطبيب
- `revision_design_done` boolean — المصمم أنهى التعديل
- `revision_approved_by_tech` boolean — الفني اعتمد التعديل
- `permanent_fabrication_done` boolean — تم تصنيع الدائم
- `permanent_shipped_to_secretary` boolean — وصل للسكرتارية
- `permanent_delivered_to_doctor` boolean — وصل للطبيب
- `final_archived` boolean — أرشفة نهائية بعد الدورة

## تغييرات الكود

### `src/lib/case-stages.ts`
- توسيع `CaseStage` لتضم: `temp_done`, `temp_shipped`, `doctor_review`, `revision`, `revision_done`, `permanent_fab`, `permanent_done`, `permanent_shipped`, `final_archived`.
- تحديث `deriveStageKey` ليعكس الفروع الجديدة بترتيب الأولوية (من الأعلى للأدنى).
- إعادة حساب النِسَب لتوزيع موحّد على الدورة كاملة.

### `src/components/case-workflow-controls.tsx`
- **عرض الطبيب** (جديد): بعد ظهور `secretary_received`، يظهر زر "تأكيد استلام المؤقت" ثم بطاقة قرار فيها زرّان:
  - "اعتماد نهائي" → يضبط `doctor_decision='approved'` + يُشعر المصمم والفني تلقائياً.
  - "طلب تعديل" → فتح Dialog لإدخال `revision_notes` ثم إرسال للمصمم.
- **المصمم**: عند وجود `doctor_decision='revision'` تظهر بطاقة "تعديل مطلوب" مع الملاحظات وزر رفع ملف التعديل وتفعيل "تم التعديل" → إشعار الفني.
- **الفني**: عند `revision_design_done` أو `doctor_decision='approved'` تظهر بطاقة "اعتماد لتصنيع الدائم"، ثم زر "تم تصنيع الدائم" يرسل للسكرتارية.
- **السكرتارية**: زر "استلام الدائم" + "ترحيل الدائم للطبيب" + زر "أرشفة نهائية".

### `src/components/designer-cases.tsx`
- إظهار شارة المرحلة الجديدة بالألوان المناسبة لكل حالة.
- عرض ملاحظات التعديل في تفاصيل الحالة عند وجودها.
- إخفاء الحالات المؤرشفة نهائياً من القائمة الافتراضية (مع تبويب "الأرشيف النهائي").

### `src/routes/doctors.$slot.tsx`
- إدراج لوحة قرار الطبيب (الفرعين) داخل بطاقة كل حالة بصلاحياته فقط.
- استدعاء `notifyRoleAboutCase` للإشعارات التلقائية لكل تحوّل.

## الإشعارات
كل تحوّل يستخدم `notifyRoleAboutCase` الحالي مع نص واضح بالعربية (مثلاً "🔔 طلب تعديل تصميم — حالة ZJ-..."، "✅ اعتماد نهائي للتصميم"، "🦷 الأسنان الدائمة جاهزة").

## الأمان والـ RLS
الجداول الحالية لها سياسات public مفتوحة (متّسق مع باقي slot_cases)، لا حاجة لتغيير RLS.

## خطوات التنفيذ
1. ميجريشن لإضافة الأعمدة الجديدة.
2. تحديث `case-stages.ts` (مراحل، اشتقاق، نِسَب).
3. توسيع `case-workflow-controls.tsx` بفروع الأدوار الأربعة.
4. تحديث `designer-cases.tsx` و`doctors.$slot.tsx` لعرض القرار والشارات.
5. اختبار سيناريوهين (اعتماد / تعديل) عبر الأدوار.
